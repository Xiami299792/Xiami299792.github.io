做演示最烦的通常不是内容，是排版：你脑子里有个样子，工具里做不出来。frontend-slides 换了个思路——**不做 PPT，做网页**。

## 它是什么

一个 Agent 技能（一份结构化的 `SKILL.md` 指令集），把"做幻灯片"当成"写前端"来做。产物是**单个 HTML 文件**：CSS、JS 全部内联，没有 npm、没有构建工具，双击就能播，发给人也不用管对方装没装 Office。

它给这套做法定了不少硬规矩，其中几条挺关键：

| 规矩 | 为什么 |
| --- | --- |
| 每页都在 1920×1080 的固定舞台上，整体等比缩放 | 手机上也是 16:9，宁可留黑边也**不重排内容** |
| 切页用 `visibility` / `opacity`，不用 `display:none` | `display` 会被后面的布局类覆盖，导致"所有页同时显示" |
| 必须带 `prefers-reduced-motion` 支持 | 有人开了"减少动态效果" |
| 不留滚动、不许溢出、不许面板重叠 | 超出就拆页，而不是把字缩小 |

它还区分两种密度：**演讲用**（一页一个观点、字大、留白多）和**阅读用**（信息自足、可以用网格和表格）。开工前它会先问你四个问题：用途、长度、内容有没有、密度哪种。

## 反"AI 味"是写进指令里的

技能里专门有一节讲这件事：不要 Inter / Roboto / Arial，不要白底紫渐变，不要模板化的布局和组件。它甚至承认自己"倾向于收敛到常见选择"，所以明确要求每次换字体、换明暗、换气质。

这条我很认同：幻灯片是最容易一眼看出"AI 做的"的东西，因为难看和好看的区别不在技术，在有没有为这个场合做过选择。

## 三种进入方式

1. **从零新建** —— 给它题目和素材，它先问清楚再动手
2. **PPT 转换** —— 把现成的 `.pptx` 转成网页版
3. **增强已有** —— 拿一份 HTML 演示给它改；改之前它会先数元素，确认加东西不会溢出，会主动拆页而不是等你发现

## 什么时候别用它

- **对方要 `.pptx`**：教室电脑、评审要求提交 Office 文件时，网页版交不了差
- **需要多人协作改**：HTML 不是同事能顺手编辑的东西（虽然它带内联编辑）
- **要套官方模板/母版**：这类需求更适合下面那篇 PPT Master
- **需要打印或交纸质稿**

## 怎么装

本机已经装了，位置在 `~/.dsh/skills/frontend-slides`（Windows：`C:\Users\你的用户名\.dsh\skills\`）。别的 Agent 想用，把仓库里的技能目录拷进对应的 skills 目录即可。
