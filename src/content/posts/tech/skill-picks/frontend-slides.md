做演示最烦的从来不是内容，是排版。你脑子里明明有个样子，工具里就是做不出来。

frontend-slides 换了个思路，不做 PPT，做网页。

## 它是什么

一个 Agent 技能，就是一份结构化的 `SKILL.md` 指令集，把做幻灯片这件事当成写前端来做。产物是单个 HTML 文件，CSS 和 JS 全部内联，没有 npm，没有构建工具，双击就能播。发给人也不用管对方有没有装 Office，这点我是真的喜欢。

它给这套做法定了一堆硬规矩，其中几条挺关键。

| 规矩 | 为什么 |
| --- | --- |
| 每页都在 1920×1080 的固定舞台上，整体等比缩放 | 手机上也是 16:9，宁可留黑边也不重排内容 |
| 切页用 `visibility` / `opacity`，不用 `display:none` | `display` 会被后面的布局类覆盖，导致所有页同时显示 |
| 必须带 `prefers-reduced-motion` 支持 | 有人开了减少动态效果 |
| 不留滚动、不许溢出、不许面板重叠 | 超出就拆页，而不是把字缩小 |

说到这个固定舞台，我一开始以为是小题大做。后来想想确实有道理，演示稿本来就是按大屏设计的，硬塞进手机只会两边都不像。

它还区分两种密度，演讲用和信息自足用。开工前它会先问你四个问题，用途、长度、内容有没有、密度哪种。

## 反 AI 味是写进指令里的

技能里专门有一节讲这件事，不要 Inter、不要 Roboto、不要 Arial，不要白底紫渐变，不要模板化的布局。

它甚至承认自己倾向于收敛到常见选择，所以明确要求每次换字体、换明暗、换气质。

这条我很认同。幻灯片是最容易一眼看出是 AI 做的东西，因为难看和好看的区别不在技术，在有没有为这个场合做过选择。

差的就是这一下。

上面这些规矩，光看文字不容易有感觉。所以我照站内那份《DSH 使用指南》里的一章做了一份十六页的速览，用的就是这个技能。

**→ [打开这份示例](/slides/dsh-guide/)**

十六比九的固定舞台，手机打开会留黑边，但版式一点没动。全文件一百来 KB，字体也内嵌在里面，没有任何外部请求，断网也能放。方向键翻页，F 全屏。

## 三种进入方式

从零新建，给它题目和素材，它先把问题问清楚再动手。PPT 转换，把现成的 `.pptx` 转成网页版。增强已有，拿一份 HTML 演示给它改，改之前它会先数元素，确认加了东西不会溢出，会主动拆页，不用等你去发现。

## 什么时候别用它

对方要 `.pptx` 的时候。教室电脑、评审要求提交 Office 文件，网页版交不了差。

需要多人协作改的时候也算了。HTML 不是同事能顺手编辑的东西。要套官方模板或者母版的，更适合下一篇要讲的 PPT Master。要打印、要交纸质稿的，也别用它。

## 怎么装

不用自己 clone，也不用记目录。跟你的 Agent 说一句就行。

```text
帮我安装这个 skill：https://github.com/zarazhangrui/frontend-slides
```

它会自己把文件放到该在的位置。装完直接说「做一份讲 XX 的幻灯片」，它就会开始问那四个问题。我自己本机这份就装在 `~/.dsh/skills/frontend-slides`，路径你都不用关心。
