本章要解决的问题：DSH 装好了，但它还不能干活。它不知道用哪个模型、不知道你的 Key、不知道可以动你电脑上的哪个文件夹、也不知道做到什么程度该停下来问你。这一章把这些一次性设好。

配置的目标只有四个：能正常用、不乱花钱、不弄坏你的文件、知道怎么找回来。

本章以设置界面为主，你不需要打开或编辑任何配置文件。

界面会随版本变化。

DSH 更新很频繁。本书核对的版本是 DSH Desktop `2.0.10`、命令行 `0.1.5-rc.1`（核对日期 2026-09）。你看到的分组名称、按钮文字、入口位置，很可能和本书描述的不一样。

所以本章不写死具体的按钮文字和位置，只写「你要找的东西长什么样」。按分组去找。

实在找不到入口时，有个通用办法：把你要做的事直接告诉对话框。例如：

```text
我想设置默认使用的模型，但我在设置界面里找不到相关的地方。请告诉我应该点哪里。
```

这比在菜单里乱点快得多。

但这个办法有个前提：输入框能打字。 如果输入框是灰的、点不动，那说明你还没选中工作区（2.1.5 节讲过），对话框这时候用不了。先按 3.3 节把工作区选上——设置界面的入口通常就在主界面的一角或侧边栏，先找到它，选完工作区再回来问。

## 3.1 打开设置界面

为什么要做这一步： 后面所有配置都在设置界面里完成。先确认你能打开它，也先知道它分成哪几栏。

怎么做：

1. 启动 DSH。桌面版的启动方式和普通软件一样，双击图标即可。
2. 在界面里找「设置」相关的入口，通常在主界面的一角，或者侧边的入口列表里。

你应该看到：一个分成若干栏的窗口或面板。左侧或上方是分类列表，右侧是这一类里的具体选项。

它大致分成这几类（名称以你的实际界面为准）：

| 你要找的类别 | 管什么 | 本章哪一节用到 |
|---|---|---|
| 模型与提供商 | 用哪个模型、Key 填在哪里、接口地址 | 3.2 |
| 工作区 | AI 被允许动手的那个文件夹 | 3.3 |
| 权限与审批 | 允许它做到什么程度、什么时候问你 | 3.4 |
| 通知 | 任务做完或失败时要不要提醒你 | 3.5 |
| 外观 | 主题、字体、窗口材质 | 3.5 |
| 插件 | 安装、启用、卸载插件 | 3.7 |

不同版本的分组划分会调整：有的把「权限」并进「工作区」里，有的把「模型」和「提供商」分成两栏。按你要设置的东西去找，不要按类别名字去找。

### 如果这一步没成功

设置界面打不开，常见的是三种情况：

1. 界面还没加载完。 刚启动的十几秒内可能没有反应。等一等再点。
2. 窗口被挡住或跑到屏幕外。 把窗口最小化再还原，或者用任务栏图标切换一次。
3. 程序没真正启动起来。 完全退出 DSH（不是关窗口，是从任务栏退出），重新打开。

三种都试过还不行，把「设置界面打不开，我点了没反应」原样发给对话框。

如果对话框也用不了（输入框是灰的，见本章开头那段），那就不是设置界面的问题，是程序本身没正常起来：从系统托盘菜单里选「退出」彻底关掉它，重新启动一次。还不行就看 3.8 节症状一。

## 3.2 填 Key 和选模型

为什么要做这一步： DSH 本身不包含那个负责思考的模型（第 1.2 节讲过）。没有 Key，它一个字都回答不了；没有指定模型，它不知道自己该用哪一个。

### 第一步：先拿到 Key

本书以 DeepSeek 官方为例（这是最省事的一条路）。申请地址：

```text
https://platform.deepseek.com/api_keys
```

流程是：注册并登录 → 进入 API Keys 页面 → 创建一个密钥 → 立刻复制。

Key 只在创建的那一刻完整显示一次，关掉页面就只剩开头几位，丢了只能重建。存在哪里、不要存在哪里，第 1.2 节已经讲过，照那个做。

先充一笔小钱。 充值入口就在同一个网站的账户或费用页面里（按钮叫「充值」或「Top up」，以实际页面为准）。第一次充最小额度就够了，用几天，看看自己一段时间的实际花费是多少。有了这个数字，第 7.3 节的省钱方法对你才有意义。

余额为 0 时，Key 是对的也调不通。 填完 Key 一直失败，先去这个页面看余额。

### 第二步：把 Key 填进去

1. 在设置界面里找到与模型提供商相关的分组。
2. 找到填写凭据（也就是 Key）的输入位置，把 Key 粘贴进去。
3. 保存。有些界面自动保存，有些需要一个明确的保存动作。

关于界面上的具体文字： 提供商配置项的标签名随版本和提供商而不同，本书不给出确切标签名 `[待核实]`。你认准两件事就够：一个是「填一串字符的地方」，一个是「接口地址」。填 Key 的输入框通常会被遮成圆点或星号。

如果用的是 DeepSeek 官方，接口地址通常不需要你手填，填了 Key 就够。要手填的时候，用这两个值之一（核对日期 2026-09）：

| 格式 | 接口地址 |
|---|---|
| OpenAI 格式 | https://api.deepseek.com |
| Anthropic 格式 | https://api.deepseek.com/anthropic |

分不清该用哪个，就用第一个。 这是通用格式。

你应该看到：保存之后，提供商那一项显示为「已配置」或类似状态，而不是空白或报错。

保存之后不需要重启。 模型路由会立即生效。如果你改了配置发现没反应，先刷新页面，不要急着重启程序。

### 第三步：选默认模型

模型决定两件事：它有多聪明，以及它每次花你多少钱。这两个是绑在一起的——越强的模型越贵。

在设置界面里找到与默认模型相关的分组，里面一般有两个选项：提供商（用哪家的服务）和模型（这家里的哪一个）。

DeepSeek 官方目前提供两个模型（出处：官方模型列表页，核对日期 2026-09）：

|  | deepseek-flash | deepseek-v4-pro |
|---|---|---|
| 定位 | 快、便宜 | 更强、更贵 |
| 上下文长度 | 1M | 1M |
| 最大输出 | 384K | 384K |
| 能不能看图 | 能 | 不能 |
| 工具调用、JSON 输出 | 支持 | 支持 |

先设成 `deepseek-flash`。 它能读图、能调用工具、速度和价格都友好，第 3 章到第 6 章的所有练习都够用。

什么时候才换 `deepseek-v4-pro`： 只有当你发现它确实做不好某件事——反复做错、理解不了要求、方案明显不对——才临时换过去，难题做完就换回来。长期把贵的当默认，等于让它改个错别字也按最贵的任务收费。

两件小事：

- 「1M 上下文」大约相当于一次能读进去几百万字的中文，对学生来说基本用不完，不用担心「文件太长读不进去」。
- 认准 `deepseek-flash` 这一个写法。 旧教程里的 `deepseek-v4-flash`、`deepseek-v4-flash-vision-exp` 虽然还能调用，但对应的模型已经下线，请求实际由新模型按 Flash 价格计费。

关于思考模式： 两个模型都默认先推理一遍再回答，更稳，但更慢也更贵。你现在不用动它。

### 如果这一步没成功

填了 Key 还是用不了，按顺序查三件事：

1. Key 复制全了吗。 Key 通常很长，复制时容易漏掉头尾。
2. 有没有多余的空格。 粘贴时有时会带上空格或换行，肉眼看不出来。清空输入框重新粘贴。
3. Key 本身有效吗。 去提供商网站看它是否还在、是否被禁用、余额是否够。

还有一种情况：Key 没问题，但网络连不上提供商的服务器，表现是长时间没反应或提示连接失败。先确认网络正常，也可以在对话框里直接问：

```text
我填好了 Key，但一直提示失败。请帮我确认是配置的问题还是网络的问题，需要我提供什么信息请告诉我。
```

不要把完整的 Key 发给它，也不要把 Key 贴进任何对话窗口。 让它看配置里的提供商名字和接口地址就够了。

## 3.3 选工作区

这是本章最重要的一节。

为什么要做这一步： 工作区就是 AI 被允许动手的那个文件夹。它在工作区里可以读、可以写、可以新建、可以删除（在权限允许的范围内）。它只能改工作区里的文件——工作区之外的文件它改不了。但要注意两点：工作区之外的文件它读得到，联网也不受这道边界限制。所以别把工作区当成一道万能墙；真正该做的是别把重要文件夹选成工作区。

工作区选得对，最坏的情况是它弄乱了这一个文件夹；选得不对，最坏的情况可能是你的作业、照片或者整个系统盘。

### 三条禁令

第一条：不要选桌面。

桌面看起来最方便，随手就能看到文件。但桌面上通常堆着你所有的临时文件、刚下载的作业、别人发你的资料。AI 在工作区里可以删除文件，而删除之后不一定能找回来。

第二条：不要选 C 盘根目录。

也就是不要选 `C:\`。这等于把整个系统盘交给它，包括所有软件、系统文件和你的全部个人数据。这一条没有商量的余地。

第三条：不要选存放重要文件的文件夹。

不要选课程资料文件夹、不要选整个「文档」文件夹、不要选照片文件夹，不要选任何你丢了会心疼的文件夹。

再补一条：不要把工作区选在要交的作业所在的文件夹里。 交作业之前让 AI 直接操作最终文件，风险不值得承担。

### 推荐做法

新建一个专门给它用的文件夹。 用文件管理器就能做，不需要命令行：

1. 找一个合适的位置。建议放在 `C:\Users\你的用户名\` 下面，或者某个你能记住的盘里。
2. 新建一个文件夹，起一个一眼能认出来的名字。建议就叫 `practice`。（用英文名，避免路径里的中文引起编码问题——第 2.4 节第 6 条讲过。）
3. 以后让它干活，先在 `practice` 里建一个子文件夹，比如 `practice\questions`，让它在这个子文件夹里做事。

好处很直接：它弄乱的永远是 `practice`，你的其他东西碰不到。 这个名字没有特殊含义，也可以用别的，只要满足「专用」「容易认出来」「不含中文」三点。

### 怎么切换工作区

工作区的切换入口在不同版本里位置不同，这里只讲要找什么。

1. 在设置界面里找到与工作区相关的分组。
2. 界面上一般会显示当前生效的文件夹路径，找到它。
3. 那里会有一个「选择文件夹」「更改」或「浏览」之类的动作。点它。
4. 在弹出的文件夹选择窗口里选中你刚建的 `practice`，然后确认保存。

有些版本允许添加多个工作区。建议第一次只加一个，避免搞不清它当前用的是哪一个。

### 怎么确认切换成功了

不要假设它成功了。先往文件夹里放一个文本文件，比如 `test.txt`，随便写一行字，然后在对话框里输入：

```text
请读一下我工作区里的 test.txt，把内容原样告诉我。
```

你应该看到： 它把那一行字原样答出来。如果说找不到文件、或者读到的是别的文件夹，就说明没切成功，回去重新选一次。

再做一步反向测试，这一步更重要：

```text
请在工作区外面新建一个文件，就叫 C:\Users\你的用户名\boundary-test.txt
```

你应该看到： 它被挡住，或者弹出审批告诉你这个操作在工作区之外。它不应该真的把文件建出来。

这一步会弹审批窗口，而你要点的是「拒绝」。

这是故意设计的：你在测工作区的边界有没有生效，所以应该被拦住。「拒绝」是这次测试的正确操作，不是出错。

认按钮的时候小心一点：弹窗上通常有两类选择——一类是「就这一次」性质的（允许一次／拒绝），另一类是「以后都这样」性质的（总是允许／不再询问／记住我的选择）。这次只点「拒绝」，不要碰任何「总是」「不再询问」的选项，否则你以后会被静默放行，而你不知道。

拒绝不会坏掉任何东西。第 3.4 节会专门讲审批弹窗怎么答。

如果它真的在工作区外建出了文件，说明工作区边界没有生效，先停下来把它设对再继续用。

### 如果这一步没成功

选完文件夹还是读不到里面的文件。 先确认你选的是文件夹本身而不是文件，再用文件管理器确认文件确实在里面。有些界面需要一个明确的保存动作才生效。

每次重启之后工作区又变回去了。 工作区在有些版本里是按配置方案（第 3.6 节）保存的。切换了配置方案，工作区跟着变是正常的。确认你一直在用同一个配置方案。

它说工作区在某个奇怪的位置。 先别继续用。打开设置界面确认一遍，改对之后再做事。

## 3.4 把权限收住

为什么要做这一步： 工作区决定了它能碰哪些文件夹，权限决定了它在这些文件夹里能做到什么程度。两个都设对，边界才完整。

先记住最要紧的一条：切到「完全访问」会把审批一起关掉，它以后不再问你。 下面两张表都在解释这一条。

### 三档权限

权限模式一共三档，记这三个词：

| 权限模式 | 能做什么 | 不能做什么 |
|---|---|---|
| 只读 | 能看文件内容、能列出文件夹里有什么 | 不能改、不能写、不能新建、不能删 |
| 工作区可写 | 在指定工作区内能读、能写、能新建、能删 | 工作区之外什么都动不了 |
| 完全访问 | 整个电脑都能读写 | 几乎没有界限，风险最高 |

- 日常使用选「工作区可写」。 这是本书的推荐设置。
- 只想让它看、不想让它改的时候，临时切到「只读」。 比如让它读一份资料并总结，你不想它顺手改动任何东西。
- 「完全访问」不要长期开着。 只在极少数你完全清楚它在做什么、而且确实需要动工作区外面文件时临时开一下，用完切回来。

本机实测的默认配置里，网络暴露范围是「仅本机回环」（核对日期 2026-09）。这是另一个层面的边界，和权限是两件事。默认只有本机能访问，你不需要改它。注意：这里说的是 DSH 自己的网络入口；第 6 章要开放端口的是你自己做的那个程序，两者不是一回事。

### 审批跟着权限走，别单独去关

审批是它做有影响的操作之前，弹出来征求你同意（第 1.3 节讲过）。

审批弹窗不是出错，是它在守规矩。 这一点要建立清楚，否则你会误以为它坏了，然后想办法把审批关掉——那是这一章最不该做的事。

审批只有「问」和「不问」两种状态，而且它跟着权限模式自动变（本机实测，核对日期 2026-09）：

| 权限模式 | 审批 |
|---|---|
| 只读 | 每次都问 |
| 工作区可写 | 每次都问 |
| 完全访问 | 完全不问 |

所以把权限留在「工作区可写」，审批就自动是最严的，不需要另外去设。

注意上面最后一行：一旦切到「完全访问」，审批会一起被关掉——这是它最危险的地方，比「能读写整个电脑」更危险，因为它不再问你了。为了省事长期开着完全访问，等于同时放弃 3.3 和 3.4 建立起来的全部保护。

### 审批弹窗怎么答

弹窗出现时先看它要做什么，再决定。

读文件——可以放行。 看文件内容不会改变任何东西。确认它读的是工作区里的文件，就可以同意。但要记住：读进来的内容会发给模型，所以别人的隐私材料、别人的作业，不要让它读。

写文件、删文件——先看清它要做什么。 看三件事：动的是哪个文件（路径是不是在你那个 `practice` 里）、是覆盖还是新建（覆盖会让原来的内容消失）、删的到底是哪个。看不懂它在做什么的时候，不要点同意。

运行命令——先看清它要做什么。 命令是它直接操作你电脑的方式，权限最大。看清这条命令动的是哪个目录，以及它是只读还是会在你的系统上装东西、改设置。一条命令你完全看不懂，就先不要放行。 先问它「这条命令是做什么的，为什么需要它」，听不懂解释就继续问，或者直接拒绝。

### 一条底线：不确定就点拒绝

不确定就点拒绝。拒绝不会坏掉任何东西。

具体说清楚「不会坏掉什么」：

- 拒绝之后它不会强行继续，它会停下来，或者换个方式再来问你，也不影响后面的对话。
- 拒绝不会删你的文件、不会改你的配置、不会让软件出问题。
- 最坏的结果只是「这件事这次没做成」，你可以重新说一遍要求。

而点错同意的后果可能是不可逆的。一边是可重来的小麻烦，一边可能是找不回来的文件。 两边的代价差得太多，所以这条规则不需要犹豫。

### 除了拒绝，还有两个更好的选择

第一，问它为什么。 拒绝之后直接在对话框里问：

```text
你刚才为什么要删这个文件？请说明理由，以及有没有别的办法达到同样的目的。
```

第二，让它换个做法。 绝大多数整理类任务，都可以用「新建一个文件」代替「改掉原文件」：

```text
请换一种不会删除或覆盖任何原有文件的做法，把新结果输出成一个新文件。
```

### 如果这一步没成功

审批弹窗太频繁，一个简单任务弹十几次。 这说明任务本身包含很多有影响的操作。不要因此关掉审批，改成这样跟它说：

```text
这个任务的操作太多，审批太频繁。请先把你要做的每一步列成清单给我看，我确认之后再让你连续执行。
```

先看清单再放行，比逐个弹窗点同意安全得多。

找不到设置权限的地方。 权限入口在不同版本里位置不同，具体标签名本书不给出 `[待核实]`。直接在对话框里问：

```text
现在我的权限模式是什么？我想改成「工作区可写」，应该在哪里改？
```

## 3.5 关掉不需要的

为什么要做这一步： 默认配置是为了照顾所有人，不是为你。通知太多会打扰你，用不上的功能模块会增加你不理解的东西。花几分钟清一遍，之后用起来会顺一些。

这一节全是可选的。拿不准的项就保持默认。

### 通知

建议：保留「失败」类通知，考虑关掉「完成」类通知。

失败通知告诉你事情没做成，需要去看一眼；完成通知在你盯着屏幕时是多余的打扰，不在电脑前时也没用。

本机实测的通知相关设置有四类：「任务完成」「任务失败」「后台任务完成」「后台任务失败」，另外有一个总开关（核对日期 2026-09）。界面里有类似选项的话，按上面的建议设：关掉两类「完成」，保留两类「失败」。 具体标签文字以你的界面为准 `[待核实]`。

### 主题和外观

建议：按自己的眼睛舒服来，其他不要动。

本机实测的主题偏好是深色（核对日期 2026-09）。深色在晚上舒服，白天环境光强时可能反而吃力。这是个人偏好，没有正确答案。

同一栏里可能还有窗口材质之类的选项（本机是 `mica`）。这类选项只影响观感，不影响功能和安全，看不懂的就不要改。

### 你暂时用不到的功能模块

设置界面里可能还有一些你完全看不懂的分组，比如启动时是否自动打开浏览器、新手引导的版本、插件市场的来源列表。

处理原则：完全看不懂的，保持默认。 这些东西要么不影响正常使用，要么由程序自己管理。你现在改它，出问题之后也不知道是哪一步改坏的。

只有一种情况要动：某项设置明显和你的直觉冲突，而且你有明确的理由，比如设置里写着启动时自动打开浏览器，但你就是不想让它自动开。这类可以关掉，因为后果完全可预期。

和模型、工作区、权限无关的设置，都可以以后再调，不是你今天必须做的功课。

## 3.6 配置文件在哪

这一节只做一件事：告诉你设置存在哪。不教你怎么改它。

知道位置有三个实际用途：改坏了知道去哪恢复，换电脑时知道搬什么，出问题时能说清你的配置在哪。

### 位置

所有设置保存在 `~/.dsh/settings.yaml`。

`~/.dsh` 是什么： 这是一个文件夹路径的简写。在 Windows 上，它就是你用户目录下的一个文件夹，完整写法是：

```text
C:\Users\你的用户名\.dsh
```

其中 `你的用户名` 换成你自己的。比如用户名是 `xiaoming`，这个文件夹就是 `C:\Users\xiaoming\.dsh`。

这个名字以点开头，在 Windows 上照样可见（实测这个文件夹没有隐藏属性）。找不到就直接在文件资源管理器的地址栏里输入上面那行路径，按回车。

### 这个文件夹里都有什么

`~/.dsh` 下面这些内容（本机实测，核对日期 2026-09）：

| 名称 | 里面是什么 |
|---|---|
| settings.yaml | 设置。你在设置界面里改的东西，基本都记在这里 |
| .credentials.yaml | 凭据，也就是你的 Key 存在的地方 |
| profiles/ | 配置方案，也就是成套的配置 |
| skills/ | 技能 |
| plugins/ | 插件 |
| sessions/ | 会话记录 |
| storages/ | 程序自己用的数据 |
| agents-anywhere/ | 程序自己用的数据 |
| attachments/ | 附件，比如你发给它的图片文件 |

重要：`.credentials.yaml` 里存着你的 Key。 这个文件不要复制给别人，不要上传到网盘，不要贴进任何提问里。要给别人看配置时，先把这一份拿掉。

### 能不能改

这些是纯文本文件，用记事本就能打开，也确实能改。但是改坏了，程序可能启动不了：多一个空格、少一个缩进、写错一个词，程序就可能读不下去，表现是启动失败或者设置全部回到默认。

所以：

- 默认不要用记事本改这些文件。 能用设置界面改的，就用设置界面改。
- 真的要改，先备份。 把原文件复制一份，文件名后面加上 `.bak-日期`，例如 `settings.yaml.bak-20260904`。出了事把这份改回原名，就等于回到改之前的状态。
- 改之前把 DSH 完全退出。

### 想看当前生效的完整配置

如果只是想知道「现在到底生效了哪些设置」，不必打开文件：

```text
dsh --dump-config
```

你应该看到：一大段文本，把当前配置方案里的各项设置列出来。这一条只用来看，不用来改，看不懂是正常的。

### 多套配置方案

`profiles/` 里可以放多套配置方案。本机就有两个：`desktop` 和 `work1`（核对日期 2026-09）。它们各存各的设置、各装各的插件，互不干扰。

一套用来做实验，一套用来做正式的事。 在 `work1` 里装一个来源不明的插件试效果，不满意直接不用它，`desktop` 里干干净净。不过第一遍配置先只管一套，用熟了再考虑加第二套。

## 3.7 装插件

为什么要做这一步： 插件（plugin）是给 DSH 加功能的程序。装上之后，界面或能力会多出东西。装插件是让 DSH 变成「你的 DSH」的主要方式。

### 装之前先看三样

插件是别人写的代码，装进来就会在你电脑上运行。

它和手机上的 App 不一样：手机 App 受应用商店审核、受系统权限框限制；插件直接跑在你的 DSH 里。审批弹窗能帮你看住一部分动作，但插件本身的行为不是每一步都会来问你。

所以装之前看三样：

1. 谁写的。 是官方出的，还是某个不认识的人发的？作者有没有能查到的其他作品？
2. 多久没更新。 长期不更新的插件，可能跟不上新版本，也可能作者已经不维护了。
3. 要什么权限。 它需要读写文件吗？需要联网吗？需要运行命令吗？一个「换个界面颜色」的插件如果要求运行命令，这个要求就不合理。

三条都说不清的，先不装。

### 方法一：用内置的插件市场（推荐）

DSH Desktop 内置了一个插件市场，可以浏览、看详情、一键安装和卸载，不用敲命令。它通常就在设置界面里，和插件相关的分组放在一起。

你要找的是「一个能搜索插件、并且有安装按钮的地方」。界面上的具体名称和位置随版本变化，本书不给确切标签 `[待核实]`，按这个特征去找就行。

逛一逛、看看别人在做什么，从这个入口开始最省事。装完记得做本节最后那一步。

### 方法二：直接在对话框里让它装

如果你已经知道要装哪个插件（别人给了你名字或者仓库地址），把这件事直接交给对话框：

```text
请帮我装 XXX 插件。先告诉我它是做什么的、要什么权限，我确认之后你再装。
装完告诉我怎么验证它生效了。
```

注意那句话里的顺序。 先让它说清「这是做什么的、要什么权限」，你确认之后它再动手。插件是别人写的代码，装进来就会在你电脑上运行，对不熟悉的来源不要直接说「帮我装」。

它装完之后，同样要做本节最后那一步。

### 方法三（备用）：命令行

界面里找不到入口、或者你想批量操作时，再到 DSH 终端（托盘菜单里打开，见 2.1.7 节）里运行这两条（核对日期 2026-09）：

```text
dsh plugin --profile desktop add @包名/插件名
```

你应该看到：一段下载和安装的过程输出。把 `@包名/插件名` 换成你要装的插件的完整名字。

```text
dsh plugin --profile desktop remove @包名/插件名
```

你应该看到：卸载过程的输出。装错了、装坏了，用这条卸掉。

不要用 `dsh plugin list` 来确认装没装上。 实测（核对日期 2026-09）它执行成功但什么都不打印——`dsh plugin` 只是把参数转发给底层的包管理器，而通过插件市场装的插件不在它管理的那份清单里。要确认装没装上，看插件市场的「已安装」列表。

不熟悉命令行的话：这两条分别是「安装」「卸载」。`--profile desktop` 是指明操作哪一套配置方案（第 3.6 节）。整条命令可以原样复制，只把插件名字换掉。用桌面版的话，这一节基本用不上。

### 装完必须重启并刷新

这是本节唯一一处讲这件事，第 4 章装技能时也是同一步。

装完插件之后，必须完全退出 DSH 并重新启动，然后刷新页面，插件才会生效。

只关窗口不算退出——关闭窗口只是收进系统托盘（见 2.1.5 节），要确保进程真的结束了（任务栏的托盘区域里没有它的图标）。刷新也一样重要：有些插件的界面部分只在页面重新加载后才出现。

装完觉得「没有任何变化」时，先问自己：重启了吗？刷新了吗？ 大多数「装了没用」都是这两步之一漏了。

### 插件的三类

插件大致分三类。第一类的两个例子是本机实测装过的（核对日期 2026-09），后两类只描述它们做什么：

第一类：改变界面外观的。 只影响你看到的样子，不影响它做什么。例如 `@deepseek-ai/dsh-client-ui-aqua`（换一套界面主题）和 `dsh-ui-font`（换界面字体）。这类风险最低，适合第一次练习。

第二类：增加或检查能力的。 让它多会做一件事，或者在你做完之后帮你检查，比如检查代码、核对结论有没有依据。这类会读你的文件、参与你的任务，风险高于第一类。

第三类：辅助记忆与生成的。 帮你记住一些事，或者自动生成一部分内容，比如按项目保存长期记忆、自动生成测试。这类会长期保存你的内容，也可能改动你的文件，装之前想清楚你愿不愿意。

### 如果这一步没成功

命令报错说找不到 `dsh`。 这只影响方法三（命令行），插件市场和对话框方式都不受影响。确实要用命令行，回到第 2 章检查安装和 PATH 相关的步骤。

命令跑完了，但插件没出现。 先按本节最后一步重启并刷新。还是不行，到插件市场里看它有没有装上、有没有被禁用。装上了但没出现，可能是这套配置方案没启用它，去设置界面的插件分组里看启用状态。

装完 DSH 启动不了。 不要慌，也不要反复重装。用 `remove` 命令把它卸掉就能回来，具体步骤在 3.8 节的症状三。

## 3.8 出问题怎么办

这一节按症状索引，找到和你情况最接近的一条照着做。

### 症状一：设置界面打不开

三步的做法和 3.1 节那张清单是同一套，这里只说不一样的下一步。

1. 等三十秒再试一次。刚启动时界面可能是空的。
2. 把窗口最小化再还原，或者从任务栏切换一次。
3. 从托盘菜单选「退出」彻底关掉它，重新启动。

三步都无效时，看症状四：你的配置文件可能有问题。

### 症状二：填了 Key 还是用不了

原因： 四种可能——Key 复制不全、带了多余空格、Key 本身失效、网络连不上。

1. 到提供商网站确认这个 Key 还在、还有额度。
2. 清空输入框，重新完整粘贴一次 Key，注意头尾不要多空格。
3. 换一个最简单的问题测试，比如「你好」。如果这个也失败，就不是模型选择的问题，回到第 1、2 步。

排查过程中不要把完整 Key 发给任何人或任何 AI。

### 症状三：装完插件 DSH 启动不了

原因： 新装的插件和当前版本不兼容，或者插件本身有问题。

1. 用命令行把那个插件卸掉：

```text
dsh plugin --profile desktop remove @包名/插件名
```

你应该看到：卸载过程的输出。

2. 卸完重启 DSH。如果还是启动不了，说明问题不在那个插件，看症状四。
3. 记不清装的是什么名字，就到插件市场的「已安装」列表里找（不要用 `dsh plugin list`，它什么都不打印）。

如果 DSH 已经启动不了、连命令也跑不动，按症状四处理。

### 症状四：改坏了配置文件

原因： 用记事本改了 `settings.yaml` 或别的文件，改出了语法错误。

1. 找到你改之前复制的备份，文件名应该带有 `.bak-日期`。
2. 把改坏的那个文件改名（比如在后面加 `.broken`），再把备份文件改回原来的名字。
3. 重启 DSH。

如果你没有备份：把 `settings.yaml` 改名挪走，重启 DSH。程序会重新生成一份默认设置。代价是模型、工作区、权限都要重新配一遍（按 3.2 到 3.4 的顺序重做），但你的文件和数据本身不会丢。

这就是 3.6 节强调「要改先备份」的原因。

### 症状五：换电脑怎么搬配置

1. 在新电脑上按第 2 章正常安装 DSH，先启动一次，让程序把 `C:\Users\你的用户名\.dsh` 这个文件夹建出来。
2. 完全退出 DSH。
3. 从旧电脑的 `~/.dsh` 里，把 `settings.yaml` 和 `.credentials.yaml` 复制到新电脑的同一个位置。
4. 旧电脑上装了插件的话，在新电脑上用 `dsh plugin --profile desktop add @包名/插件名` 一条条重新装上。插件不适合直接复制文件夹，重新装更可靠。
5. 旧电脑上有你自己写的技能（第 4 章），把 `skills/` 文件夹也复制过去。
6. 重启 DSH，然后按 3.3 节的方法测试工作区。新电脑上的路径不一样，工作区必须重新选一次。

两条注意：

- `.credentials.yaml` 里是明文 Key。 不要用微信、QQ 传，不要经过公共电脑，用 U 盘或你自己的私有方式。
- 不要把旧的 `sessions/` 一起搬过来。 会话记录通常很大，在新电脑上也没有用。

### 如果这些办法都试过还不行

把原始报错原样复制下来（不要转述），发给对话框，或者去提问。判断「是我操作错了还是教程过时了」的方法，第 7.1 节会讲。

有一条通用原则：求助时给原文，不给你的概括。 报错信息里的每一个字都可能是线索。

## 本章验收

配置做完，用下面四项确认。四项都过，本章就算完成。

一、Key 能正常用。

在对话框里发一句最简单的话，比如「你好」，它应该能正常回答。答不出来就回到 3.2 节。

二、工作区已经改成你的练习目录。

在 `practice` 里放一个 `test.txt`，让它说出这个文件里写了什么，它要能读到。回到 3.3 节。

三、权限设成「工作区可写」。

打开设置界面，确认当前权限模式是「工作区可写」，审批策略保持最严的那一档（每次都问）。回到 3.4 节。

四、装上一个插件并能看到效果。

建议先从改变界面外观的插件开始，效果最直观、风险最低。装完按 3.7 节最后一步重启并刷新，然后确认界面上出现了变化，或者在插件列表里看到它是启用状态。

四项里有任何一项没过，先解决它，再进入第 4 章。

验收：Key 能正常用 + 工作区已改成练习目录 + 权限设成工作区可写 + 装上一个插件并能看到效果。

基础篇解决的是「能用起来」；这一篇解决的是「用得住、用得好」。你会把反复要提的要求写成技能，让它自动照做；会组一个评审团检查自己的产出，而不是自己夸自己；会知道怎么把话说清楚、怎么把每次踩的坑留下来，让它下次不再犯。读完这一篇，你手里有的不是一堆命令，而是一套能重复用的做法。
