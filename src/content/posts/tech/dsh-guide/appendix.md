## 附录 A｜命令速查卡

### A.1 DSH

这一页是备查，不是教程。 桌面版日常几乎用不到这些命令——在对话框里说清楚要什么，让它去做就行。只有界面里解决不了、或者你想自己管插件时，才回来查。

| 用途 | 命令 | 你应该看到 |
|---|---|---|
| 看版本 | dsh --version | 一行版本号，如 0.1.5-rc.1 |
| 看帮助 | dsh --help | 用法说明和全部选项 |
| 启动网页版 | dsh web | 终端打印访问地址 |
| 装插件 | dsh plugin --profile desktop add <名称> | 安装过程输出；装完要重启 |
| 卸插件 | dsh plugin --profile desktop remove <名称> | 卸载过程输出 |
| 用某套配置启动 | dsh --profile <名字> | 按该配置启动 |
| 从模板新建配置 | dsh --profile <新名字> --from-default-profile web | 创建成功提示 |
| 看当前完整配置 | dsh --dump-config | 打印完整配置树 |

装插件之后要重启并刷新，否则界面上看不到变化（见 3.7 节最后一步）。

### A.2 OpenClaw

| 用途 | 命令 | 你应该看到 |  |
|---|---|---|---|
| 安装（Windows） | `iwr -useb https://openclaw.ai/install.ps1 \ | iex` | 检测系统、装 Node、装 OpenClaw、进入新手引导 |
| 安装但不跑引导 | & ([scriptblock]::Create((iwr -useb https://openclaw.ai/install.ps1))) -NoOnboard | 装完停在命令行 |  |
| 安装（macOS / Linux / WSL2） | `curl -fsSL https://openclaw.ai/install.sh \ | bash` | 同上 |
| 新手引导 | openclaw onboard | 一步一步问你要填什么 |  |
| 装后台服务 | openclaw onboard --install-daemon | 开机后自动运行 |  |
| 看版本 | openclaw --version | 一行版本号 |  |
| 体检 | openclaw doctor | 各项检查结果 |  |
| 看服务状态 | openclaw gateway status | running 表示在上班 |  |
| 更新 | openclaw update --channel stable | 更新过程输出 |  |

### A.3 排查用

| 用途 | 命令 | 说明 |
|---|---|---|
| 看 Node 装没装 | node -v | 没输出说明没装或不在 PATH 里 |
| 看全局包装在哪 | npm prefix -g | 得到一个路径 |
| 看 PATH 里有什么 | $env:PATH | 确认上面那个路径在不在里面 |
| 进技能目录 | cd $HOME\.dsh\skills | 手动装技能时用 |
| 下载一个技能仓库 | git clone <仓库地址> | 在技能目录里执行；这是备用方式，优先直接让 AI 装，见 4.7.1 |

在系统终端里报「不是内部或外部命令」= `dsh` 不在 PATH 里。 桌面版用户可以忽略；确实要用命令行版，就按 `node -v` → `npm prefix -g` → `$env:PATH` 的顺序查。

### A.4 关键路径

| 是什么 | 路径 |
|---|---|
| DSH 数据目录 | ~/.dsh（Windows：C:\Users\你的用户名\.dsh） |
| 设置 | ~/.dsh/settings.yaml |
| 凭据（Key） | ~/.dsh/.credentials.yaml |
| 技能 | ~/.dsh/skills/<技能名>/SKILL.md |
| 插件 | ~/.dsh/plugins/ |
| 配置方案 | ~/.dsh/profiles/<方案名>/ |
| 会话记录 | ~/.dsh/sessions/ |

技能的层级只有一种是对的：`~/.dsh/skills/<技能名>/SKILL.md`。 多套一层文件夹就不会被加载。

## 附录 B｜术语卡

这里只收「会让你卡住的操作类词」。 概念类的词（DSH、API、Key、Agent、会话、技能、子代理、工作区、权限……）在第 1.4 节分组讲过，不在这里重复——遇到不认识的词先查这张表，找不到再回 1.4。

| 词 | 一行说明 |
|---|---|
| 终端 / PowerShell | Windows 上敲命令的那个黑窗口。开始菜单搜「PowerShell」就能打开 |
| 命令 / 命令行 | 在终端里输入的一行指令，按回车执行 |
| 路径 | 一个文件在电脑里的位置，例如 C:\Users\xiaoming\文档 |
| ~ | 代表「当前用户的主目录」。Windows 上等价于 C:\Users\你的用户名 |
| %USERPROFILE% | 同上，Windows 的写法，可以直接粘进文件资源管理器的地址栏 |
| 环境变量 PATH | 一张「去哪找程序」的清单。装了程序却提示「不是内部或外部命令」，就是它没进这张清单 |
| Node / npm / npx | 装命令行工具时才需要的运行环境（Node）和它带的两个工具（npm 装东西、npx 临时跑一下）。桌面版自带，你不用管它 |
| 端口 | 一台电脑上区分不同服务的小号码。被占用时程序会自动换一个 |
| 局域网 / 内网 | 同一个 WiFi 里的设备组成的网络，只有同网络的人能互相访问 |
| 隐藏文件夹 | 名字以 . 开头的文件夹（Unix 传统）。Windows 上照样可见，.dsh 就是可见的，不用去开「显示隐藏的项目」 |
| 数字签名 | 软件发布者用来证明「这东西是我发布的」的电子签名。实测的桌面版安装包没有，所以别用它判断真伪 |
| 开源 / MIT | 代码公开、可以自由使用和修改。DSH Desktop 就是这种 |

## 附录 C｜提示词模板 16 个

以下都可以直接复制，把方括号里的内容换成你自己的。

### C.1 万能追问句（用得最多的一句）

```text
先别动手。先问我最多 5 个问题，把我的需求问清楚，再给我方案，我确认后你再做。
```

### C.2 做文档之前先问清楚

```text
先别动手。先问我四个问题：这份东西给谁看、大概多长、要什么格式、必须包含哪几点。
问完给我一个提纲，我确认后你再写。
```

### C.3 要改文件之前先看计划

```text
先别动手。先告诉我你打算改哪些文件、每个文件改什么、改完之后会变成什么样。
我同意之后你再改。
```

### C.4 查资料之前先复述

```text
先把我问的问题复述一遍，确认你理解对了，再开始查。
```

### C.5 报错求助（第 7.1 节）

```text
我在做什么：
我执行的命令或操作：
我期望的结果：
实际发生的结果：
完整报错（原文粘贴，不要删减）：
我已经试过：
```

### C.6 让 AI 读更新日志

```text
这是 DSH 的更新日志。不要给我摘要。请回答三个问题：
一、哪些改动会影响到我现在的用法？
二、有哪些我一直在用的东西被改掉了，我需要做什么？
三、有没有新增的、对我有用的能力？
```

### C.7 把成功做法回写成技能

```text
把刚才这次的做法整理成一个技能，写到 ~/.dsh/skills/ 下。
要求：description 里写上我会说的那几句话；步骤写成可执行的动作；
加上产出要求和自检清单；再加一节「如果做不到」。
写完告诉我这个技能会在什么情况下被触发。
```

### C.8 技能库体检

```text
检查 ~/.dsh/skills/ 下所有的技能，告诉我哪些内容重复了、
哪些步骤可能已经过时、哪些从来没有被触发过。
```

### C.9 单人反向复核（第 5.8 节）

```text
你的唯一任务是找出这份内容的问题。只写问题，不要写优点，也不要写总结。
至少找出五个。
```

### C.10 让 AI 出题考你

```text
根据我们刚才讲的内容，出五道题考我，先不要给答案。
```

### C.11 检查有没有泄露隐私

```text
检查这份文件，列出所有可能泄露个人信息的内容：真实姓名、学号、手机号、
邮箱、密码、密钥、IP 地址、本机路径。逐条指出在哪一行。
```

### C.12 让它换一种说法

```text
这个我没听懂。换一个说法再讲一遍，不要用行话，假设我完全没接触过这个领域。
```

### C.13 让它标出不确定的地方

```text
凡是你不确定的内容，标上 [不确定]，并说明你不确定的原因。
不要猜，也不要为了看起来完整而补全。
```

### C.14 明确「不要什么」

```text
不要：不要加总结段，不要用「综上所述」，不要改我原文的标点，
不要把专业名词换成通俗说法，不要在结尾问我还有没有别的需要。
```

### C.15 增量修改，不要重说一遍

```text
在上一版基础上改三处：
1. （第一处改什么，写清楚位置和要求）
2. （第二处）
3. （第三处）
其他部分一律不要动，包括标点。
```

### C.16 部署后验证（第 6.8 节）

```text
我把项目部署到了静态托管上。请帮我验证它是否真的可用：
1. 列出这个项目需要哪些后端接口（从源码里找）。
2. 针对每一个接口，给出可以在浏览器里直接访问的完整网址，让我逐个测。
3. 告诉我如果接口不存在，页面上会表现成什么样。
```

## 附录 D｜评审团工具包

### D.1 三个角色的提示词

事实与逻辑审查员

```text
你是一名事实与逻辑审查员。你的职责是检查这个产出里的客观问题，
不考虑表达风格。
检查范围：
1. 事实性错误：有没有说错、算错的地方。
2. 数据来源：每一个数字、日期、比例，有没有交代出处。
3. 内部一致性：前后有没有矛盾，比如前面说三步、后面出现四个步骤。
4. 推理或逻辑跳跃：有没有从 A 直接跳到 C，中间缺了一步。
输出格式：
- 先给一个总分（满分 25 分），只评事实与逻辑。
- 逐条列出问题，每条写明：位置 + 问题 + 建议怎么改。
- 每条建议必须具体到能直接动手改，不要写「论证不足」这类无法执行的话。
- 如果确实没发现问题，说明你检查了哪些方面，而不是只说「没有问题」。
不要评价表达，不要夸奖。只写问题。
待审内容：
（在这里粘贴，或说明它在哪个文件）
```

使用方代表

```text
你是一名使用方代表。你的身份是：（写清楚谁用它，例如
「大一新生，第一次参加这个活动」，或者「接手这段代码的下一届同学」）。
你的任务是从使用者的角度找出会卡住的地方。
检查范围：
1. 哪里需要看第二遍才能懂。
2. 哪些前提是作者默认成立、但在我这里不成立的。
3. 哪些地方缺少必要的说明或步骤。
4. 按它说的做，我能不能顺利走完。
输出格式：
- 先给一个总分（满分 25 分），只评可用性与适配程度。
- 逐条列出卡住的位置，写明：在哪里 + 为什么卡住 + 建议怎么改。
- 最后用一句话回答：按这个做，我能不能完成我要做的事？
不要评价专业水平。你是使用者，不是专家。只写你用不了的地方。
待审内容：
（在这里粘贴）
```

风险与合规审查员

```text
你是一名风险与合规审查员。你的职责是检查这个产出在引用、标注、
安全和规范上有没有问题。
检查范围：
1. 引用：引用他人观点、数据、素材的地方，有没有标明来源。
2. AI 参与：如果有 AI 参与，有没有如实说明。
3. 隐私：有没有出现真实姓名、学号、联系方式、密码、密钥、IP 地址等
   不该出现的信息。
4. 硬性要求：篇幅、格式、命名等规定有没有做到。
5. 风险：有没有可能造成损失、争议或事故的地方。
输出格式：
- 先给一个总分（满分 25 分），只评合规与风险。
- 逐条列出问题，写明位置 + 问题 + 怎么改。
- 特别标出任何属于「必须改，不改会出事」的问题。
不要评价质量高低。只写规范与风险。
待审内容：
（在这里粘贴）
```

## 附录 E｜版本锚点与勘误页

### E.0 报错先看这张表

你遇到报错时，先在这里按报错里出现的那句话找一行，它告诉你去哪一节。找不到再来读 E.1 往下。

| 报错里出现的话 | 大概率是什么问题 | 去哪一节 |
|---|---|---|
| 不是内部或外部命令、command not found | 在系统终端里找不到 dsh：装了但系统不知道装在哪。桌面版用户可以直接忽略这一条 | A.3（三步排查） |
| EPERM、EACCES、权限不足、拒绝访问 | 权限不够、被杀软拦住，或者（Windows 上）直接调用了 .cmd 程序 | 第 2.4 节「杀软拦截」；第 3.4 节「审批弹窗怎么答」；第 6.6.3 节 |
| EADDRINUSE、端口被占用、address already in use | 端口冲突 | 第 2.4 节「端口被占用」；第 6.5.4 节 |
| UnauthorizedAccess、禁止运行脚本 | PowerShell 执行策略拦住了 | 第 2.2.3 节 |
| 找不到文件、路径无效、文件时有时无 | 路径含中文，或在 OneDrive 同步目录里 | 第 2.4 节「路径含中文」 |
| 版本不满足、requires Node | 只有命令行版或 OpenClaw 才有 Node 版本要求（桌面版自带运行环境，不会遇到）；也可能是版本要求变了，教程已经过时 | E.1 对版本号；第 7.1.4 节「教程过时的五个信号」 |
| npm error code | 安装过程失败 | 第 7.1 节：把报错原文按模板交给 AI |
| 完全看不懂 | 不要猜 | 第 7.1 节（报错怎么喂给 AI） |

两条通用建议：

- 报错原文不要转述，整段复制（第 7.1.1 节）。
- 排查命令（`node -v`、`npm prefix -g`、`$env:PATH`）要在 PowerShell 里敲，不是在 CMD 里——`$env:PATH` 这一条只在 PowerShell 能用。

### E.1 版本锚点

本书核对于 2026 年 9 月。

| 组件 | 核对版本 | 从哪来的 |
|---|---|---|
| DSH 命令行 | 0.1.5-rc.1 | 运行 dsh --version 实测 |
| DSH 桌面版 | 2.0.10 | 官网 dshdesktop.cn 的发布页与仓库 Releases |
| Node（命令行版/OpenClaw 环境） | v24.18.0 | 作者本机实测 |
| OpenClaw | 2026.7.1-2 | 运行 openclaw --version 实测 |

命令报错时，先做两件事：

1. 对一下你的版本号和上表是否接近。差得远，说明书里的内容可能已经过时。
2. 把报错原文交给 AI，让它判断是不是版本变化导致的。

本书里凡是对外的事实（价格、模型名、界面能力），出处只有三类：官方文档、官方仓库（README 与 Releases）、或者作者本机实测。第 7.10 节那条纪律——一手来源里没有的，不当事实用——对这本书自己也一样。你发现哪一条没有出处、又和实际不符，按 E.4 记一笔。

### E.2 已知的不确定项

下面这些内容，本书没有完全验证，使用前请留意。我宁可标出来，也不想用笃定的语气写一件我没试过的事。

| 项目 | 状态 | 说明 |
|---|---|---|
| DSH 命令行版对 Node 的版本要求 | [待核实] | 以官方文档为准；桌面版自带运行环境，不需要你单独装 Node |
| 桌面版内置的 Node / pnpm 具体版本号 | [待核实] | 桌面版自带运行环境，不需要你安装；升级时会一起更新，不影响使用 |
| ~/.dsh/agents-anywhere/ 目录的用途 | [待核实] | 只确认了目录存在，未查证具体作用 |

| 修改 PowerShell 执行策略 | 条件性建议 | 不在 OpenClaw 官方文档中。只在系统报「禁止运行脚本」时才做，不要提前改 |

### E.4 勘误页怎么用

如果你发现本书的某条命令跑不通，按这个格式记一笔，写在你自己的工作区里：

```text
日期：
书里的位置：（第几章第几节）
书上写的：
实际情况：
我是怎么解决的：
```

这个习惯的价值不只在这本书上。 第 7.8 节讲的「环境档案」，用的就是同一套方法——把踩过的坑记下来，下次不用重新趟一遍。

这本书里所有内容都会过时，但记录和更新的方法不会。
