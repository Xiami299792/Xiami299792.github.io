这一章要解决的问题：把 DSH 装到你的电脑上，再顺手装一个 OpenClaw。装完你要能用 DSH 做完一件小事，并且跟 OpenClaw 说过一句话。

全章分四段：2.1 装 DSH 是主线；2.2、2.3 是选做（装 OpenClaw 以及为什么装两个），可以最后再回来做；2.4 是故障索引。每一段都能单独停下来。

两个工具各自独立，互不依赖。装 DSH 不需要先装 OpenClaw，反过来也一样。

版本说明：本章核对日期 2026-09。桌面版核对版本 `2.0.10`，命令行版核对版本 `0.1.5-rc.1`。软件更新很快，你下载到的版本号比这里新是正常的。

## 2.1 安装 DSH

### 2.1.1 先认识 DSH Desktop

你要装的是 DSH Desktop。你可能在网上看到好几个名字很像的东西，先分清。

DSH Desktop 是一个装在自己电脑上的 AI 工作台，双击图标就能打开。装完还不能干活——它需要一个模型，第 3 章会教你怎么接上。

它是社区项目，不是 DeepSeek 官方出品的。由 anywhere-labs 团队开发并开源（MIT 协议，代码仓库 `github.com/anywhere-labs/dsh-desktop`），官网是 `https://dshdesktop.cn`。

它开源、免费。有人以任何形式要卖给你，别买。

上面那个仓库地址你不用打开。它只是告诉你这个项目是谁做的、开不开源。你现在要打开的只有下一节给出的那一个下载页。

为什么本书选它，而不是官方那一套？理由很直接：

- 一键下载、开箱即用。运行需要的东西它都自带，你不需要装任何环境，也不需要敲任何命令（官方那条路要你自己装 Node）。
- 装完就是一个完整的界面，第 3 章到第 6 章的所有操作都在这个界面里完成。
- 桌面版还内置手机遥控（iOS 和 Android），可以在手机上远程操作电脑上的它。

官方自己还提供另一套用法。等你会用了想换，随时可以换——2.1.8 节会单独介绍那个东西，你现在只要记住一件事：先装 DSH Desktop。

### 2.1.2 下载 DSH Desktop

为什么先做这一步：这个程序装上去之后能读写你的文件，所以安装文件必须来自可信的地方。网盘、群文件、第三方软件站下载的文件有被替换过的风险。

打开浏览器，访问这个页面（本书的安装步骤只用这一个网址）：

```text
https://dshdesktop.cn
```

页面上有 Windows 和 macOS 两个入口，按你的电脑选一个，不要两个都下：

| 你的电脑 | 下载哪个 | 大小 |
|---|---|---|
| Windows（绝大多数人） | DSH-Desktop-2.0.10-x64-Setup.exe | 约 148.8 MB |
| Mac | DSH.Desktop-2.0.10-universal.dmg | 约 304.5 MB |

下载页可能先弹一个小窗口（一般是邀请你去 GitHub 点 Star）。关掉它，下载会自动开始。认准「下载」两个字就行。

下载下来先花三秒看一眼文件名。本书能确认的就是上表里那两个名字（核对日期 2026-09）：Windows 是 `DSH-Desktop-2.0.10-x64-Setup.exe`，Mac 是 `DSH.Desktop-2.0.10-universal.dmg`。文件名里带版本号是正常的，你下到的版本号比这里新也是正常的，不用专门去找旧版。看文件名只判断两件事：

- 是不是从上面那个页面下载的，文件名对不对得上。文件只有几百 KB 说明没下载完整，要删掉重新下一次。
- 文件名里夹着「破解」「绿色版」「修改版」「汉化版」这类字眼的，删掉重下。正规发布不会加这些词。

关于数字签名，这里必须说清楚，否则你会被别处的教程卡住。很多教程教你下载后右键看「属性」、在「数字签名」那一栏确认签名者名称。这对很多软件有效，但对 DSH 的安装包不适用：实测作者本地的 2.0.9 安装包（核对日期 2026-09）没有数字签名，那一栏是空的（2.0.10 未复测；无论有没有签名，判断真伪都只看下载渠道和文件名）。

所以不要用「有没有签名」来判断真伪，否则你会卡在这一步，或者误以为下载到了假文件。判断来源只看两件事：是不是从上面那个页面下载的，以及文件名正不正常。

没有签名这件事有一个直接后果：安装时 Windows 会给你一个警告（下一节讲）。这是正常的，不是你操作错了。

### 2.1.3 运行安装程序

双击那个 `.exe` 文件。Windows 会弹出一个窗口问「你要允许此应用对你的设备进行更改吗」，选「是」。

如果你用的是 Mac：打开下载好的 `.dmg`，把 `DSH Desktop` 拖进「应用程序」。

安装过程本身没有需要你选的选项，一路用默认值即可。默认的安装位置是系统盘的程序目录，不要改。有些教程会让你装到 D 盘，那是为了省系统盘空间，代价是以后出问题的概率变高，不值得。

装完之后，在开始菜单（Mac 上是「启动台」）里找到 `DSH Desktop`，或者在桌面上看到它的图标。

### 2.1.4 两个会拦你的提示

这两件事几乎每个人第一次装都会遇到，先讲清楚，免得你以为自己操作错了。

第一个：未知发布者。

运行安装程序时，如果弹出「Windows 已保护你的电脑」这样的蓝色窗口，写着你未知发布者。这是 Windows 对不常见的安装程序给的提示，不是中病毒。

处理办法：在窗口上点「更多信息」，再点「仍要运行」。

这个提示出现的原因很直接：这个安装包没有买数字签名证书（上一节说过），Windows 无法确认发布者是谁，就把这个判断交给你。

所以这里的「仍要运行」是你确认来源之后自己做出的判断，不是绕过安全机制。前提是你确实是从官方网站下载的。如果你是从群里、网盘里拿到的文件，这个提示就应该让你停下来。

第二个：杀毒软件提示。

装到一半或者刚装完，杀毒软件可能弹出警告，说这个程序有风险，甚至直接把它移到隔离区。

这类提示常见于国产杀软和 Windows 自带的实时防护，原因是新程序的某些行为会触发它们的规则，不一定说明程序有问题。但也不要无脑放行。

处理顺序：

1. 先确认安装包是从上面那个下载页面拿的（注意：这个安装包没有数字签名，不能用签名来判断，只能看下载渠道和文件名）；
2. 确认之后，在杀毒软件的提示窗口里选「允许」或者从隔离区恢复，不要直接关掉整个杀毒软件；
3. 如果每次启动都被拦，就要考虑下载的版本不对，回官网重新下一份。

不要为了装一个程序把杀毒软件永久关掉。这一条没有例外。

### 2.1.5 第一次启动

在开始菜单或桌面双击 `DSH Desktop`。

第一次启动会比以后慢一些，它在自己的目录里建初始文件。

第一次启动会先弹出一个设置向导，问你要窗口样式、要不要通知、要不要用系统浏览器打开等等。这个向导可以一路跳过，后面随时能在设置里改。注意：向导没走完、也没跳过之前，主界面不会出来，所以别以为它卡住了。

进到主界面，就算启动成功了。你会遇到三种情况，都属于正常：

情况一：对话输入框是灰的，打不了字。这不是坏了。官方文档明确说明：在选中工作区之前，会话输入框不可用。工作区就是 AI 被允许动手的那个文件夹，你还没告诉它该在哪个文件夹里干活，所以它不接受指令。设置工作区是第 3.3 节的内容，按那里做完就能打字了。

情况二：界面里空空荡荡，让你添加工作区。同上，这是第一次打开的正常状态。

情况三：它直接就能打字。说明它已经默认选中了某个目录（通常是启动时所在的目录）。这种情况你更要认真做第 3.3 节——因为它自动选的那个目录可能并不合适。

现在先不要配置任何东西，也不要填 Key。配置是第 3 章的内容，这里只要它能打开就够。

关窗口不等于退出。关闭窗口只是收进系统托盘，程序还在跑；要从托盘菜单里选「退出」，才是真的结束。

看完把窗口关掉也可以，它只是收进托盘，没有别的影响。

### 2.1.6 你的数据存在哪里

为什么要知道这个：DSH 的所有配置、会话记录、技能、插件都在一个目录里。以后备份、迁移、彻底重装，都要用到它。不知道它在哪，就没法备份。

这个目录是：

```text
~/.dsh
```

`~` 这个符号表示「当前用户的主目录」。在 Windows 上，它就是你自己的用户文件夹，也就是 `C:\Users\你的用户名\.dsh`。例如你的 Windows 用户名是 `xiaoming`，完整路径就是 `C:\Users\xiaoming\.dsh`。

`你的用户名` 是占位符，换成你自己的。以后本书提到 `~/.dsh`，都按这个意思理解，不再重复说明。

想直接看到它，用这个办法：打开「文件资源管理器」，在最上面那条地址栏里输入下面这一行，按回车。

```text
%USERPROFILE%\.dsh
```

按回车之后，地址栏会变成你的完整用户目录，窗口里显示出 DSH 的文件。`%USERPROFILE%` 就是 Windows 里代表「当前用户主目录」的写法，效果和 `~` 一样。

目录里的东西，你认识这六个就够了（核对日期 2026-09）：

| 名字 | 里面是什么 |
|---|---|
| skills/ | 技能。第 4 章专门讲 |
| plugins/ | 插件。给 DSH 加功能的程序 |
| sessions/ | 会话记录。你和它说过的每一段话 |
| profiles/ | 配置方案。可以准备多套设置，互不干扰 |
| settings.yaml | 设置。界面里改的东西都存在这里 |
| .credentials.yaml | 凭据。你填的 Key 存在这份文件里 |

其余几个（`storages/`、`attachments/` 等）是它自己用的中间数据，不用管。

最后两行是文件不是文件夹，不要用记事本打开乱改——界面里能改的都从界面改。这一节你只要知道它们在哪儿就行。

### 2.1.7 命令行工具（可以跳过）

桌面版装好后，命令行工具跟着安装包一起装上了，桌面版的托盘菜单里也能打开一个 DSH 终端。但本书后面的内容基本不需要你敲命令——绝大多数事情都可以直接在对话框里跟它说，让它去做。

这一节可以跳过。如果你好奇，或者想确认命令行工具确实在，就往下做。

为什么还要提它：万一将来遇到界面解决不了的问题，有个终端可用。第 3.7 节会给一条备用命令，那时候再回来敲也不迟。

打开 DSH 终端：在系统托盘的 DSH 图标上右键，菜单里选「终端」。会弹出一个窗口，里面有一行文字和一个光标。（系统自带的「终端（PowerShell）」里多半找不到 dsh 命令，原因见下面「如果这一步没成功」。）

在这个窗口里输入下面这一行，然后按回车：

```text
dsh --version
```

终端会打印一行版本号，形如 `0.1.5-rc.1`。本书核对的命令行版本就是这个（核对日期 2026-09）。你的可能更新。

版本号比这里新是正常的，不代表你装错了。

再敲一条，看看这个命令都能做什么：

```text
dsh --help
```

它会打出一屏说明文字，列出可用的选项和子命令。核对日期 2026-09，这份列表里真实存在这些选项：`--profile <name>`、`--from-default-profile <name>`、`--patch <path>`、`--dump-config`、`--dump-default-config`，以及两个子命令 `web` 和 `plugin`。

现在不用理解它们的意思。第 3.7 节会把其中两条当备用命令列出来，其余的在附录 A 里。

### 如果这一步没成功

提示「dsh 不是内部或外部命令」。这是第 2.4 节第 1 条的典型症状：命令没被系统找到。用桌面版的话，这一段可以直接跳过，不影响后面任何一章。只有确实要用命令行版时，才需要处理：先关掉终端窗口，重新打开一次再试。还是不行，按 2.4 节第 1 条处理。

终端窗口里出现一片红字。先看最后几行说了什么，通常有一句是原因。不要关掉窗口，照着 2.4 节的症状表对一下。

### 2.1.8 另一个东西：DSH（DeepSeek Harness）

第 1.1 节提过这个名字，这里补全它是什么。

DSH 是 DeepSeek 官方的项目，一个 AI Agent 运行框架，目前处于技术预览阶段（核对日期 2026-09）。官方文档在 `https://deepseek-harness.github.io/deepseek-harness/`（根路径是 404，要用这个完整地址）。

你可能已经见过它了：如果上一节你敲过 `dsh --version`，打印出版本号的那个 `dsh` 命令就是官方本体——桌面版把它一起装进来了。跳过上一节也不影响理解，一句话：DSH Desktop 是外壳，DeepSeek Harness 是里面那台机器。

官方那条路也能直接用：

```text
dsh web
```

终端会打印出几行信息，其中一行是一个网址。以终端实际打印的为准，不要照抄别人的地址；如果端口被占用，它会启动失败并打印报错，这时换一个端口重新启动。在浏览器里打开，界面和桌面版一样。代价是关掉终端它就停了。

两条路用同一套数据目录和技能格式，你在第 4 章写的技能两边都能用。随时可以换，不用重来。

### 2.1.9 升级、卸载，以及卸载时必须做的事

升级。桌面版有新版时按程序里的提示更新。也可以用新的安装包重新装一遍，覆盖安装不会删除 `~/.dsh` 里的配置和会话记录。

卸载。分两步，缺一不可。

第一步，走系统卸载程序：打开「设置」，找到「应用」里的「已安装的应用」，在列表里找到 `DSH Desktop`，选「卸载」。

第二步，手动删除数据目录 `~/.dsh`（Windows 上是 `C:\Users\你的用户名\.dsh`）。卸载程序不会替你删这个目录。

第二步删掉之后就找不回来了。你会同时失去：全部会话记录、全部技能、全部配置和你填过的 Key。

如果你以后可能还想用，删除之前先把整个 `.dsh` 文件夹复制一份到别的地方，例如移动硬盘。复制完成后再删。

只想清空对话、保留配置的话，不要去删整个目录，第 7.2 节讲按会话清理的正确做法。

### 如果这一步没成功

看不到 `DSH Desktop` 的程序条目，说明安装其实没有完成。重新运行一次安装包，注意观察有没有中途报错，然后按 2.4 节第 5 条检查杀软是否把它拦掉了。

## 2.2 选做：安装 OpenClaw

### 2.2.1 为什么还要装一个

DSH 要你坐到电脑前，打开它，把任务交给它。有些事你不想坐到电脑前，比如早上出门前想起来今天要交作业，比如在手机上想问一句「上次那个文件我放哪了」。

OpenClaw 补的就是这一类场景。它常驻在你自己的对话窗口里，你在哪都能给它发消息。具体分工见 2.3 节，这里先把安装做完。

本节全部内容依据 OpenClaw 官方安装文档编写（核对日期 2026-09）：<https://docs.openclaw.ai/zh-CN/install>

### 2.2.2 系统要求

官方文档写的要求是：

- Node 22.22.3+、24.15+ 或 25.9+；
- 支持 macOS、Linux、Windows。

Node 是什么：一个让这类程序跑起来的运行环境。你不需要提前了解它。

安装脚本会自动处理 Node。你不需要自己去下载安装 Node。脚本会检查你电脑上有没有、版本够不够，不够就替你装好。你也不需要知道 `22.22.3` 是什么意思。

只有一种情况例外：如果你电脑上本来就装了 Node，而且版本比较旧，脚本会去处理它。这时它可能问你要不要装新版 `[待核实]` 具体会问什么，按提示选同意就行。

### 2.2.3 如果系统拦住脚本，再回来做这一步

这一小节现在不用做。跳过它，直接去 2.2.4。

只有当你执行 2.2.4 的命令、看到「禁止运行脚本」这类报错时，再回到这里读。

为什么会拦：Windows 默认不允许直接运行脚本文件，这是一道安全机制，不是你的操作出了问题。大部分人的电脑能直接跑通 2.2.4，所以不要提前去改这个设置。

真的遇到那个报错时，打开「终端（PowerShell）」，输入下面这一行，按回车：

```text
Get-ExecutionPolicy
```

正常的话，会打印出一行单词，可能是 `Restricted`、`RemoteSigned`、`AllSigned`、`Unrestricted`、`Bypass` 或 `Undefined` 中的一个（前两个最常见）。

如果它显示的是 `Restricted`，输入下面这一行，按回车：

```text
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

接着它会问你确认。输入 `Y` 再按回车，然后没有报错，直接回到等待输入的状态。

这一条命令的意思是：本地自己写的脚本可以直接运行；从网上下载的脚本必须有可信签名才允许运行。它只对你自己这个账号生效，不需要管理员权限。

装完 OpenClaw 之后，如果想把这个设置改回去，把上面那条命令末尾的 `RemoteSigned` 换成 `Restricted`，再执行一次即可。

### 2.2.4 推荐方式：一条命令

在同一个「终端（PowerShell）」窗口里，输入下面这一行，按回车：

```text
iwr -useb https://openclaw.ai/install.ps1 | iex
```

这一行的意思是：从官方地址取回安装脚本，然后执行它。`iwr` 是 PowerShell 里「从网上取一个文件」的命令，`iex` 是「把取回来的内容当作命令执行」。

终端里会开始一行一行往外打印内容。它会报告正在检查 Node、正在安装、进度如何。这个过程通常几分钟，看你的网速。

中途不要关窗口。装完之后它会自动进入新手引导。

如果你只想装、暂时不跑引导，用这一条：

```text
& ([scriptblock]::Create((iwr -useb https://openclaw.ai/install.ps1))) -NoOnboard
```

过程和上一条类似，只是结束时不会进入引导提问环节，直接回到等待输入的状态。之后你想补上引导，任何时候敲 `openclaw onboard` 都可以。

### 2.2.5 macOS 和 Linux 用户

如果你用的是 Mac，或者在 Windows 里装了 WSL2（一个在 Windows 里跑 Linux 的环境），用的是另一条命令：

```text
curl -fsSL https://openclaw.ai/install.sh | bash
```

终端里同样逐行打印安装进度，和 Windows 版一样。

本书以 Windows 为主线，Mac 和 WSL2 的读者把这一条命令替换进去即可，其余步骤一致。

### 如果这一步没成功

报错里出现「禁止运行脚本」或 `UnauthorizedAccess`。说明你需要按 2.2.3 节放开执行策略，或者你把它放到了别的终端窗口里。重新打开一个终端，做完 2.2.3 再试。

下载中途停住、进度不动。先等两分钟。还是不动就按 `Ctrl + C` 中断，重跑一遍同样的命令。网络波动导致的失败重跑一次通常就好了。

报错里出现证书、TLS、SSL 字样。常见于校园网，处理办法见 2.4 节第 4 条。

装完了但敲 `openclaw` 提示找不到命令。见 2.2.8 和 2.4 节第 1 条。

### 2.2.6 新手引导

安装脚本结束时通常会自动进入新手引导。如果它没有自动开始，或者你用了 `-NoOnboard`，自己敲这一条开始：

```text
openclaw onboard
```

终端里会出现一问一答的引导流程，它会问你几个问题，每个问题都给出可选项。

按提示回答即可。有几处可以补充说明：

- 它问的那些设置里，涉及模型和 Key 的选项，用你第 3 章要填的那个 Key（第 3 章会讲怎么申请）。Key 的示例写法是 `你的密钥`，那是占位符。
- 涉及聊天渠道的选项，如果你只是先试试，可以先跳过，以后再加。
- 拿不准的选项，直接按回车用它的默认值。默认值是官方推荐的，比随便选更稳。

建议加一个参数，顺带装后台服务。用这一条代替上一条：

```text
openclaw onboard --install-daemon
```

区别是：装完之后，OpenClaw 会作为后台服务一直在跑，重启电脑之后它还在，不需要你每次手动启动。不加这个参数，重启后它就不跑了，你得自己再启动一次。

对本书读者，建议加上。

### 2.2.7 验收：三条命令

官方文档给的三条验收命令，都在「终端（PowerShell）」里执行。三条都跑一遍再往下走。

第一条，确认命令可用：

```text
openclaw --version
```

输出是一行版本号。本书核对的 OpenClaw 版本是 `2026.7.1-2`（核对日期 2026-09），你的比这个新是正常的。

第二条，检查配置有没有问题：

```text
openclaw doctor
```

终端会逐项检查并打印结果，正常情况下每一行都是通过或提示，最后给出总结。如果某一行写着错误，把它那一段原文记下来，按 2.4 节处理，不要跳过。

第三条，确认后台服务正在运行：

```text
openclaw gateway status
```

输出是一行服务状态说明，写着正在运行。

第三条失败是最常见的。通常是因为后台服务还没启动。先试试：

```text
openclaw gateway restart
```

然后再跑一次 `openclaw gateway status`。还是不行的话，重新执行一次新手引导并带上后台服务参数：

```text
openclaw onboard --install-daemon
```

### 2.2.8 找不到 openclaw 命令怎么办

这几乎总是 PATH 问题。PATH 是一张「敲了命令名之后去哪些文件夹找程序」的清单——程序装好了，但装的位置不在清单上，系统就找不到它。

按顺序敲这三条：

```text
node -v
npm prefix -g
$env:PATH
```

三条的输出分别是：第一条打印版本号（形如 `v24.18.0`）；第二条打印一个文件夹路径；第三条打印一长串用分号隔开的路径。

把第二条那个路径和第三条的内容对一下——如果第二条不在第三条里，就是它的问题。

修法两种，选简单的那种：重跑一次 2.2.4 的安装脚本，它会重新处理环境变量。处理完必须关掉终端窗口重新开一个再试（旧窗口不会自动更新）。还不行就手动加：设置里搜「环境变量」→ 用户变量里的 `Path` → 把第二条打印的路径加进去 → 重开终端。

这三条命令的完整说明在附录 A.3，报错索引在附录 E.0。

### 2.2.9 其他安装方式（不推荐新手）

官方文档还提供了这些方式。列出来是为了让你在别处看到它们时知道那是什么，每一种对新手都有额外的坑，本书都不推荐。

| 方式 | 说明 |
|---|---|
| 本地前缀安装脚本 | 把程序和 Node 都装到 ~/.openclaw 下 |
| npm / pnpm / bun 手动装 | 要你自己管好 Node，版本不对就会失败 |
| 从源码构建 | 需要 git、pnpm 和编译环境 |
| 从 GitHub main 检出 | 跟的是还没发布的最新改动，可能不稳定 |

为什么本书不教这些：它们都要求你先理解 Node、包管理器和编译环境是什么。你现在要做的是把工具用起来，不是学这一套。等走完全书、对这套东西有感觉了，再回来挑一条也不迟。

Windows 上还有一个图形化的选择：官方提供原生的 Windows Hub 客户端，带设置、托盘状态、聊天窗口和诊断，从开始菜单启动，不用敲命令。它对不熟悉终端的人更友好，而且可以和命令行版同时用。但本书的验收命令仍然以命令行版为准。

来源：`docs.openclaw.ai/zh-CN/platforms/windows`

### 2.2.10 更新

以后要更新 OpenClaw，用这一条：

```text
openclaw update --channel stable
```

它会检测当前的安装方式，取回新版本，跑一次自检，然后重启后台服务。结束后会打印新的版本号。

`--channel` 后面跟的是「渠道」，也就是跟着哪条线更新：

- `stable` 是稳定版，改动经过完整测试才发布。只用这一个。
- `dev` 是开发版，直接跟代码仓库的最新改动，可能刚改完还没测。名字里带 dev 就是开发的意思。

`dev` 上有新功能，但也会有半成品和坏掉的版本。你现在的目标是把这个工具用起来，不是帮它找问题。不要为了尝鲜切到 dev。

更新完按 2.2.7 节的三条命令再验一遍，确认没问题。

## 2.3 选做：为什么要装两个

### 2.3.1 它们在两个地方工作

这两个工具不是一回事，也不互相替代。区别在于你在哪里用它、以及它被允许做什么。

OpenClaw 的入口是对话窗口，你在手机上、在教室、在走路的时候都能发消息给它。它适合处理你随口交代的小事。

DSH 的入口是你的电脑，要打开浏览器或者它的界面。它能直接读你电脑里的文件、改文件、跑多步的长任务。它适合处理那些需要坐下来认真做的东西。

OpenClaw 管你在外面的事，DSH 管你坐到电脑前的事。

### 2.3.2 分工表

|  | OpenClaw | DSH |
|---|---|---|
| 在哪用 | 对话窗口里，随手使唤 | 电脑前，浏览器打开 |
| 擅长 | 提醒、记事、整理、查资料 | 读文件、改文件、多步长任务 |
| 典型任务 | 每天早上推待办 | 把一堆资料整理成一份文档 |

看这张表就能判断一件事该交给谁。判断方法只有一条：这件事需要碰到你电脑里的文件吗？需要就找 DSH，不需要就先找 OpenClaw。

再补两句表里放不下的区别：

- 装一次之后，OpenClaw 常驻在对话窗口里，你不需要专门打开什么；DSH 每次都要你打开它。
- DSH 能做长时间、多步骤的任务，中间还会停下来问你；OpenClaw 更适合说一句、答一句。

### 2.3.3 两种组合用法

单独用哪一个都能用。两个一起用，能省掉一些反复的操作。

组合一：管家收集，工程师干活。

你在课上或者路上想到什么、看到什么链接、听到什么要求，顺手发给 OpenClaw，让它记下来、整理成一段话。等你回到电脑前，把整理好的那段话交给 DSH，让它去读文件、改文件、做成成品。

适合的场景：小组作业分头收集资料，最后要合成一份文档；或者一天里陆陆续续想到的待办，晚上一次性处理。

组合二：工程师产出，管家提醒。

DSH 在电脑上做完一份东西，比如整理出一份复习提纲。你把「每天提醒我复习一遍第三章」交给 OpenClaw，之后它按时间提醒你。

适合的场景：有截止日期的事、需要反复看的东西、需要按时做的例行任务。

两种用法的共同点是：收集和提醒交给 OpenClaw，动手改文件交给 DSH。反过来的话，OpenClaw 碰不到你的文件，DSH 又需要你坐到电脑前，都别扭。

### 2.3.4 能不能只装一个

可以，但要知道代价。

只装 DSH：你在教室、路上就没办法用它，所有事都要攒到回电脑前。而且没有人提醒你。

只装 OpenClaw：它能对话、能查资料，但它碰不到你电脑里的文件。第 6 章那个刷题程序，靠它做不出来。

如果你时间有限，先装 DSH，把它用顺。第 3 章到第 6 章都以它为主，OpenClaw 是补充。等你觉得「要是有个东西能提醒我就好了」，再回头装 OpenClaw 也不迟——它随时能补装，不影响 DSH。

### 2.3.5 三个常见的疑问

两个都要填 Key 吗？是。它们各自要连模型，各自的 Key 填在各自的地方。DSH 的 Key 填在它的设置界面里（第 3 章讲）；OpenClaw 的 Key 在它的新手引导里填。不要图省事在两边填同一个 Key 然后到处复制，Key 泄露的后果算在你头上。示例里一律写 `你的密钥`，那是占位符。

先装哪个？顺序不影响结果，两个互不依赖。建议先装 DSH，因为后面几章立刻要用到；OpenClaw 可以在这一章直接装完，也可以留到以后。

两个一起用会不会互相干扰？不会。它们装在不同的位置，数据也分开存放，同时运行没有冲突。

## 2.4 出问题怎么办

这一节按症状索引，不按原因。你遇到什么现象，就找哪一条。每条给三步以内的做法。

### 1. 提示「不是内部或外部命令」「找不到命令」

用桌面版的话，PATH 排查可以直接跳过：所有操作都在界面里完成，不依赖这条命令。只有命令行版和 OpenClaw 才需要处理 PATH。

症状：敲 `dsh` 或 `openclaw` 之后，终端说找不到这个命令，但程序明明装好了。

原因：安装的位置不在系统查找清单（PATH）里。这是最常见的一类问题。

做法：

1. 关掉终端窗口，重新打开一个。安装程序更新了环境变量，旧窗口读不到。
2. 还是不行，按 2.2.8 节敲那三条命令，把 `npm prefix -g` 打印的路径和 `$env:PATH` 的内容对一下。
3. 路径确实不在清单里，重跑一次 OpenClaw 的安装脚本（2.2.4 节），装完再次关掉并重开终端。仍然不行就手动把那个路径加进用户环境变量。

### 2. Node 版本不满足（只有命令行版和 OpenClaw 会遇到）

桌面版自带运行环境，不会遇到 Node 版本问题，可以直接跳过。这条排查只针对 OpenClaw 的安装脚本，以及你自己在系统里用命令行版的情况。

症状：安装脚本报错，说 Node 版本太低或者不符合要求。

原因：你电脑上原本装了一个旧版 Node，OpenClaw 的安装脚本没有覆盖它。

做法：

1. 不要自己去网上找 Node 安装包乱装。先把报错原文完整复制下来。
2. 重新跑一次 2.2.4 节的安装脚本。脚本会重新检查并处理 Node，这是它设计好的行为。
3. 如果它反复报同一个错，用 `node -v` 看一下当前版本，把这一行连同报错一起，按第 7.1 节的求助模板去问。

补充：如果你之前为了别的课程装过 Node，版本又旧，脚本会试图处理它。这时它可能问你要不要装新版，按提示选同意。

### 3. 执行策略被拦（装 OpenClaw 时会遇到）

症状：终端里一片红字，出现「禁止运行脚本」「无法加载文件」「UnauthorizedAccess」这类字样。

原因：Windows 默认不允许直接运行从网上取回的脚本。这一条只在装 OpenClaw、跑它的安装脚本时出现（2.2.4 节）。

做法：

1. 打开「终端（PowerShell）」，敲 `Get-ExecutionPolicy` 看当前状态。
2. 结果不是 `Restricted` 的话，问题不在这里，去查第 1 条。
3. 是 `Restricted` 的话，敲下面这行，回答 `Y`，然后关掉窗口重新打开，再跑安装命令：

```text
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

不要用「以管理员身份运行」来解决这个问题，也不需要关掉整个安全策略。上面这条只改你自己账号的设置，装完可以改回去，详细说明在 2.2.3 节。

### 4. 校园网超时、证书错误（只有 OpenClaw 和命令行版会遇到）

桌面版的安装包只有一百多 MB，从官网直接下载，通常不会遇到这类问题。这条排查针对的是 OpenClaw 的安装脚本，以及命令行版从网上取依赖时的场景。

症状：安装脚本下载中途停住、进度长时间不动，或者报错里出现证书、TLS、SSL、`unable to verify` 之类的字样。

原因：校园网通常有代理和流量审计，会拦截或替换证书，安装脚本连不上官方地址。

做法：

1. 换网络再试。用手机热点是最快的一条路，装完再切回校园网。
2. 换了网络还是失败，看报错里的地址，那个地址应该以 `openclaw.ai` 或 `deepseek` 相关域名开头。地址不对说明下载源被换掉了，停下来，重新核对本书给的命令。
3. 学校的网络中心通常有校内镜像或代理配置说明。如果你不确定怎么配代理，去问网络中心，不要在网上随便找一份代理配置照抄。

不要为了让某个命令通过而关掉系统的证书校验。证书出错也可能是真的有中间人在改你的流量，这条底线不要破。

### 5. 杀软拦截

症状：安装程序打不开、装到一半消失、装完之后程序启动不了或文件不见了；杀软弹出警告说发现威胁。

原因：杀软对不常见的程序行为敏感，误报很常见。

做法：

1. 先确认安装包是从上面那个下载页面拿的（注意：实测的 DSH 安装包没有数字签名，所以不能用签名来判断，只能看下载渠道和文件名）。
2. 确认之后，在杀软的提示窗口里选「允许」「信任」或从隔离区恢复，不要直接把整个杀软关掉。
3. 修好之后按 2.1.5 节重新启动一遍，或者按 2.2.7 节重新验一遍 OpenClaw。

如果你记不清这个文件是从哪来的，不要放行。删掉，回官网重新下载。判断标准是来源，不是签名。

### 6. 路径含中文，或者在 OneDrive 同步目录里

症状：程序能装，但运行时报错，说找不到文件、路径无效、权限不足；或者文件时有时无、改完又变回去。

原因：两个常见来源。一是你的 Windows 用户名是中文，于是 `C:\Users\你的用户名\.dsh` 这条路径里带中文；二是你把工作区设在了 OneDrive、坚果云这类同步文件夹里。

做法：

1. 先看路径。按 2.1.6 节打开 `~/.dsh`，看地址栏里有没有中文字符。
2. 如果用户名是中文，数据目录这一处通常仍能正常工作；真正容易出问题的是你的工作区。第 3 章选工作区时，不要选带中文的路径，也不要选同步目录。
3. 同步目录的问题在于：文件一边被同步程序上传或回滚，一边被程序改写，两边会打架。把工作区换到本地一个纯英文、不同步的文件夹，比如 `C:\work`。

### 7. 端口被占用

症状：启动网页版时终端报错，出现 `EADDRINUSE`、`address already in use`、端口被占用之类的字样。

原因：那个端口号已经被别的程序用了。

做法：

1. 端口被占用时会启动失败，换一个端口重新启动即可。启动成功后以终端实际打印的地址为准，不要照抄上一次或别人的地址。
2. 如果你手动指定过端口，去掉那个指定，让它自己挑。
3. 如果你是在用 `dsh web`，先关掉之前没关干净的终端窗口，再重新启动。

不要把端口号写死在任何地方。每次启动都以终端打印出来的那一行为准。地址形如 `http://127.0.0.1:端口号`，其中端口号部分以实际打印为准。

### 8. 装崩了，想彻底重来

症状：装到一半断电、程序打不开、配置被改乱、装了好几遍越装越乱。

原因：不用找原因。走到这一步，重来一遍比修快。

做法：

1. 先备份。把整个 `~/.dsh` 文件夹复制一份到别处。里面有你的会话记录、技能和配置，删掉就找不回来了。注意这份备份里有 `.credentials.yaml`，你的 Key 在里面是明文——不要把它放到网盘、U 盘借人或者任何会被别人拿到的地方。
2. 卸载程序。走系统卸载程序（2.1.9 节第一步）。
3. 删干净再装。删掉 `~/.dsh` 目录，然后重新运行安装包。如果想保留原来的会话和技能，装完之后再把备份里的 `sessions/` 和 `skills/` 复制回去；只想干净重来就什么都不复制。

OpenClaw 装崩了同理：先按官方文档的卸载说明移除，再重跑 2.2.4 节的安装脚本。重装前把 `~/.openclaw` 里的配置备份一份。

重装 DSH 不会影响 OpenClaw，反过来也一样。两个可以分别处理。

## 本章验收

按顺序做完下面四件事，本章就算过了。

第一件：DSH 能报出版本号。在托盘菜单里打开 DSH 终端（也可以打开「终端（PowerShell）」），敲：

```text
dsh --version
```

应该看到一行版本号，形如 `0.1.5-rc.1`。

第二件：桌面版能打开。在开始菜单启动 `DSH Desktop`，走完或跳过首次的设置向导，能看到主界面。不需要在里面配置任何东西，看到界面就关掉也算通过。

第三件（选做）：让 DSH 报告它自己的情况。如果输入框能打字，就发一句话：

```text
请告诉我：你现在的模型是什么？我的工作区是哪个文件夹？我现在的权限模式是什么？
```

你不需要看懂它的全部回答，只要它正常回了话（而不是报错），这一件就算过。

输入框是灰的、打不了字？跳过这一件。那说明它还没选中工作区（2.1.5 节讲过），第 3 章配好工作区之后再做。打不了字是因为还没选工作区。等第 3 章填好 Key 之后，它才真的能回话——这两件事有先后，别弄混。

第四件：OpenClaw 三条命令全过，并且跟它说过一句话。

```text
openclaw --version
openclaw doctor
openclaw gateway status
```

三条都有正常输出，没有报错。然后在新手引导里、或者在它连上的对话窗口里随便说一句话，收到它的回复。

验收：`dsh --version` 打印出版本号，`DSH Desktop` 能打开并进到主界面，`openclaw --version`、`openclaw doctor`、`openclaw gateway status` 三条命令都正常输出，并且你已经跟 OpenClaw 说过一句话并收到回复。（第三件是选做；第四件要先装 2.2 节的 OpenClaw，跳过 2.2 的话这一件也跳过。）本章真正必做的是前两件：能报出版本号、能打开主界面。
